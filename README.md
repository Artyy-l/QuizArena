# QuizArena

QuizArena — учебное веб-приложение для создания квизов с помощью ИИ, одиночного прохождения и игры с другими участниками. Интерфейс и генерируемые вопросы рассчитаны на русский язык.

## Что умеет приложение

- Создавать квиз по теме или загруженному материалу, отслеживать статус генерации и редактировать параметры квиза.
- Генерировать вопросы с одним ответом, несколькими ответами, формата «верно/неверно» и «100 к 1». В вариантах «100 к 1» модель оценивает относительную популярность ответов и назначает баллы.
- Проводить одиночные попытки с таймером, ставкой в специальном вопросе и таблицей лидеров.
- Создавать совместную сессию, приглашать участников по коду и смотреть результаты игры.
- Хранить историю прохождений, копировать квизы и скачивать исходный материал, если он был загружен.
- Показывать математические формулы в вопросах, ответах и пояснениях.

Копия квиза получает собственные настройки, вопросы, варианты ответов и отдельную копию материала. Попытки игроков и их результаты в копию не переносятся.

## Как устроена генерация

1. Java-приложение сохраняет квиз и отправляет задачу генерации через Kafka.
2. Если приложен файл, Java-приложение извлекает из него текст с помощью Apache Tika и передаёт этот текст вместе с темой в LLM-сервис.
3. Python/FastAPI-сервис обращается к OpenAI-совместимому API и возвращает структурированные вопросы.
4. Java-приложение проверяет и сохраняет вопросы в PostgreSQL. Статус генерации отображается в интерфейсе.

В текущем веб-сценарии файл **не передаётся модели напрямую**: изображения, схемы и формулы, которые не удалось извлечь как текст, могут не попасть в генерацию. Если из файла совсем не удалось получить текст, задача завершится ошибкой. Поддерживаются `.pdf`, `.txt`, `.doc`, `.docx`; через интерфейс загружается один файл размером до 5 МБ. При создании квиза интерфейс позволяет выбрать от 1 до 30 вопросов для прохождения; приложение обычно генерирует пул из 30 вопросов, из которого формируется попытка.

## Стек

Java 17, Spring Boot 3.2, Spring MVC, Spring Data JPA, Spring Security, Thymeleaf, Maven; Python 3.11 и FastAPI для LLM-сервиса; PostgreSQL, Redis и Kafka; Docker Compose для локального запуска.

## Быстрый запуск

Нужны Docker Desktop или Docker Engine с Compose и API-ключ провайдера, совместимого с OpenAI API.

1. Создайте `.env` на основе шаблона:

   ```bash
   cp .env.example .env
   ```

   В PowerShell используйте `Copy-Item .env.example .env`.

2. Укажите в `.env` значение `OPENAI_API_KEY`. При необходимости измените `OPENAI_BASE_URL`, `OPENAI_MODEL` и `ETHICS_MODEL`. Пример рассчитан на Polza.ai и модель `openai/gpt-6-luna-pro`; доступность выбранной модели зависит от вашего провайдера.

3. Запустите приложение с необходимыми сервисами:

   ```bash
   docker compose up -d --build app
   ```

4. Откройте [http://localhost:8081](http://localhost:8081). Проверка состояния приложения: [http://localhost:8081/actuator/health](http://localhost:8081/actuator/health).

Состояние контейнеров: `docker compose ps`. Логи приложения: `docker compose logs -f app`. Остановка: `docker compose down`. Последняя команда сохраняет данные в Docker volumes; не используйте `down -v`, если хотите сохранить квизы и историю.

Приложение доступно на порту `8081`, LLM-сервис — на `8000`. Для локальной разработки PostgreSQL проброшен на `5433`, Redis — на `6380`, Kafka — на `9092`.

Проверить Kafka после запуска можно так:

```bash
docker compose exec kafka /opt/kafka/bin/kafka-topics.sh \
  --bootstrap-server localhost:9092 --list
docker compose exec kafka /opt/kafka/bin/kafka-consumer-groups.sh \
  --bootstrap-server localhost:9092 --describe --group quiz-generation-worker
```

У consumer не должно быть отставания (`LAG`) после обработки очереди. При создании квиза задача генерации появляется в `quiz-generation-requests`, а временные ошибки автоматически повторяются; после исчерпания попыток сообщение попадает в `quiz-generation-requests-dlt`.

## Основные страницы

| Страница | Адрес |
| --- | --- |
| Вход и регистрация | `/login`, `/register` |
| Каталог квизов | `/home` |
| Создание и список своих квизов | `/quiz/create`, `/my-quizzes` |
| Страница квиза | `/quiz/{quizId}` |
| История и профиль | `/history`, `/profile`, `/edit-profile` |
| Совместная игра | `/multiplayer/create`, `/multiplayer/join` |

На странице квиза можно начать прохождение, сделать копию квиза и скачать материал, если он есть. Приватный квиз и его материал доступны только автору.

## API и авторизация

Веб-интерфейс работает с REST API в `/api/`. Например, `POST /api/quizzes` создаёт квиз, `POST /api/quizzes/{quizId}/materials` загружает материал, `GET /api/quizzes/{quizId}/generation-status` показывает состояние генерации, `POST /api/attempts/answer` отправляет ответ, а `GET /api/quizzes/{quizId}/materials/download` скачивает материал.

После входа API использует JWT. Для запросов, изменяющих данные, нужен заголовок `Authorization: Bearer <token>`; переданный клиентом `userId` не даёт прав действовать от имени другого пользователя. Не публикуйте `.env` и JWT-токены.

## Проверки

Для Java нужен JDK 17 или 21. Из корня проекта:

```bash
mvn test
node --test src/test/js/*.test.cjs
```

В Docker сборка выполняется на JDK 17. Если локально используется JDK 23, для Mockito-тестов нужен экспериментальный режим Byte Buddy:

```bash
mvn "-DargLine=-Dnet.bytebuddy.experimental=true" test
```

Тесты Python-сервиса запускаются из его каталога после установки зависимостей из `requirements.txt`:

```bash
cd LLM_service
python -m unittest discover -s tests -v
```

Профиль `dev` использует H2 вместо PostgreSQL, но сам по себе не запускает Kafka, Redis и LLM-сервис. Для полной проверки генерации удобнее использовать Docker Compose.

## Каталоги

- `src/` — Java-приложение, шаблоны страниц и тесты;
- `LLM_service/` — сервис генерации вопросов и его тесты;
- `docs/` — документы по курсовой работе;
- `docker-compose.yml` — локальная инфраструктура.
